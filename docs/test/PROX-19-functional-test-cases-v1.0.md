## 1. 编号与字段约定

- 用例 ID：`TC-<模块>-<序号>`。
  - `CRW`：抓取触发（看板粘贴 / 扩展点击 / 幂等 / 失败态）
  - `PRE`：预览抽屉与保存
  - `DUP`：去重提示与字段覆盖
  - `CRD`：看板卡片展示
  - `EXT`：浏览器扩展交互
  - `SEC`：安全 / 鉴权 / CORS
  - `RAT`：频率限制与 LLM 截断
  - `REG`：回归与边界
- 每条字段：优先级（P0 = 直接对应 AC/BR，P1 = 重要辅助）、类型（正向 / 负例 / 边界 / 回归）、前置条件、步骤、预期结果、追溯（AC / FR / BR / 技设§）。
- "扩展调用"指通过 Chrome/Edge MV3 扩展向本地后端发起请求；"Web UI" 指浏览器中 React SPA 操作。

## 3. 用例正文

### 3.1 抓取触发（CRW，AC-1/3/4/7/9/12）

**TC-CRW-01**（P0·正向）看板粘贴 BOSS 直聘链接解析成功
- 前置：已登录 Web UI，进入岗位看板。
- 步骤：点击「添加岗位」→ 粘贴 `https://www.zhipin.com/job_detail/xxxx.html` → 发起抓取。
- 预期：30 秒内解析完成并打开预览抽屉；`fields` 中 company、title、jd_url、location 非空；confidence 中 company/title 为 high；数据库 `job` 表无新增记录。
- 追溯：AC-1、FR-1/10/12、BR-20。

**TC-CRW-02**（P0·正向）看板粘贴牛客网链接解析成功
- 步骤：同 TC-CRW-01，URL 为 `https://www.nowcoder.com/job/xxxx`。
- 预期：同 TC-CRW-01，source 识别为 `nowcoder`。
- 追溯：AC-1、SITE-2。

**TC-CRW-03**（P0·正向）扩展在 BOSS 直聘详情页一键抓取
- 前置：扩展已安装并配置有效 Agent Bearer key；当前标签页为 BOSS 直聘 JD 详情页。
- 步骤：点击扩展工具栏按钮。
- 预期：扩展弹窗显示解析中；30 秒内自动打开浏览器新标签页 `/#/jobs/new?prefill=...` 并进入预览抽屉；`CrawlResult.status` 为 `ok`。
- 追溯：AC-9、FR-2、§12.3。

**TC-CRW-04**（P0·正向）扩展在牛客网详情页一键抓取
- 步骤：同 TC-CRW-03，当前页为牛客网 JD 详情页。
- 预期：同 TC-CRW-03，source 为 `nowcoder`。
- 追溯：AC-9、SITE-2。

**TC-CRW-05**（P1·正向）看板粘贴猎聘 / 实习僧链接解析成功
- 步骤：分别粘贴猎聘、实习僧 JD 链接发起抓取。
- 预期：30 秒内返回 `ok` 或 `partial`，并进入预览抽屉；source 分别为 `liepin`、`shixiseng`。
- 追溯：SITE-3/4、FR-3。

**TC-CRW-06**（P1·正向）公司官网 LLM 兜底路径解析
- 步骤：粘贴某企业校招官网 JD 链接（`source=official`）或扩展在公司官网页面点击抓取。
- 预期：后端走 LLM 抽取，30 秒内返回 `ok` 或 `partial`；返回 `fields` 至少包含 company、title、jd_url；confidence 有字段级标记。
- 追溯：AC-12、FR-15、SITE-5、§8.3。

**TC-CRW-07**（P0·边界）30 秒内同一 request_id 幂等
- 前置：准备同一 URL 与同一 `request_id`。
- 步骤：在 30 秒内连续 3 次粘贴该链接（Web UI 链路固定同一 request_id）或扩展连续点击 3 次。
- 预期：后端仅产生一次解析任务；3 次均返回同一 CrawlResult（`request_id` 相同、字段值相同、响应时间后两次明显更短）；数据库 `crawl_attempt` 表仅新增 1 条记录或 3 条均指向同一结果（以技设口径为准，不生成多个岗位）。
- 追溯：AC-7、FR-4、BR-4、技设 §3.4。

**TC-CRW-08**（P1·边界）同一 URL 不同 request_id 重新解析
- 步骤：同一链接换新的 `request_id` 再次发起抓取。
- 预期：后端重新执行解析任务，返回新 CrawlResult；`crawl_attempt` 表新增独立记录。
- 追溯：BR-4。

**TC-CRW-09**（P0·异常）解析超时进入手动录入
- 前置：通过测试钩子或构造慢响应，使 `/jobs/crawl` 处理时间 > 30s。
- 步骤：发起抓取后等待。
- 预期：30s 后接口返回 `status=timeout`；Web UI / 扩展展示「解析超时」提示，并提供「重试」与「手动录入」入口；点击手动录入后进入 `/#/jobs/new?url=...`，URL 已预填。
- 追溯：AC-4、FR-13/32、§11。

**TC-CRW-10**（P0·异常）目标页 403 / 网络异常进入手动录入
- 前置：通过测试钩子或构造目标站返回 403 / 连接失败。
- 步骤：发起抓取。
- 预期：接口返回 `status=fetch_failed`，error_message 含原因；Web UI / 扩展给出「重试」与「手动录入」入口；手动录入页预填 URL 与已解析字段（如有）。
- 追溯：AC-4、FR-31/32、§11。

**TC-CRW-11**（P0·异常）不支持的站点
- 步骤：粘贴一个非 SITE-1~5 的链接（如某招聘论坛详情页）。
- 预期：接口返回 `status=unsupported_site`；Web UI / 扩展提示「暂不支持该站点，已为您切换到手动录入」；手动录入页 URL 已预填。
- 追溯：AC-3、FR-30、§11。

**TC-CRW-12**（P1·异常）partial 状态：字段缺失过半
- 前置：构造解析结果中公司、岗位名至少一项为空，或核心字段缺失过半。
- 步骤：发起抓取并进入预览抽屉。
- 预期：预览抽屉标记缺失字段（warning 描边 / 「待补全」角标）；保存按钮置灰并提示补全必填项；用户补全后保存按钮可点击。
- 追溯：AC-6、FR-12、§11。

### 3.2 预览抽屉与保存（PRE，AC-1/5/6）

**TC-PRE-01**（P0·正向）预览抽屉字段与置信度展示
- 前置：已完成一次成功抓取（TC-CRW-01）。
- 步骤：查看预览抽屉。
- 预期：展示 company、title、location、deadline、description、requirements（degree/experience/salary/tags）及 source；每个字段旁显示 confidence（high/medium/low）；缺失字段显示「未识别」占位。
- 追溯：FR-12、§8.6。

**TC-PRE-02**（P0·正向）修改岗位名后保存
- 步骤：在预览抽屉将岗位名改为「后端开发工程师（实习）」→ 点击保存。
- 预期：保存成功后跳转岗位看板；看板卡片展示修改后的岗位名；数据库记录与 CrawlResult 原值不一致处为用户修改值。
- 追溯：AC-1、FR-12、BR-11。

**TC-PRE-03**（P0·负例）公司名或岗位名为空保存置灰
- 步骤：清空预览抽屉中的公司名或岗位名，观察保存按钮。
- 预期：保存按钮 disabled；行内标红并提示「必填」；点击无效，不调用 `POST /jobs`。
- 追溯：AC-6、FR-12。

**TC-PRE-04**（P0·负例）不经确认不自动保存
- 步骤：完成 TC-CRW-01 后，在预览抽屉出现前 / 出现后均不点击保存，直接关闭抽屉或离开页面。
- 预期：数据库 `job` 表始终无新增记录；`crawl_attempt` 表仅有解析记录，无对应 job_id。
- 追溯：AC-5、BR-20。

**TC-PRE-05**（P1·边界）关闭抽屉后重新进入保留编辑态
- 步骤：预览抽屉中修改字段但未保存，误点抽屉外蒙层关闭；再次通过同一 `prefill` 链接进入。
- 预期：以技设口径为准；若实现为关闭即丢弃，则重新进入显示原始解析值；若实现为草稿保留，则显示修改值。记录实际行为，不得出现数据错乱或自动保存。
- 追溯：FR-12。

### 3.3 去重提示与字段覆盖（DUP，AC-2）

**TC-DUP-01**（P0·正向）重复提示 + 更新该岗位
- 前置：已存在岗位 J1（公司 A / 岗位 X / 工作地点 北京）。
- 步骤：再次抓取同一公司同一岗位的新链接 → 预览抽屉点击保存 → 弹出重复提示 → 选择「更新该岗位」。
- 预期：J1 的工作地点被新解析值覆盖；J1 的 id 不变；投递记录与状态历史保留；被覆盖字段有更新日志（以技设/PROX-3 口径为准）。
- 追溯：AC-2、FR-20/21、BR-1/10。

**TC-DUP-02**（P0·正向）重复提示 + 新建为不同岗位
- 步骤：同 TC-DUP-01，在重复提示中选择「新建为不同岗位」。
- 预期：强制创建新岗位 J2；允许用户修改公司 / 岗位名以区分；保存成功后看板出现两条记录。
- 追溯：FR-22、BR-3。

**TC-DUP-03**（P0·正向）重复提示 + 取消
- 步骤：同 TC-DUP-01，在重复提示中选择「取消」。
- 预期：不创建 / 不更新岗位；返回预览抽屉或看板，数据无变化。
- 追溯：FR-20。

### 3.4 看板卡片展示（CRD，AC-8）

**TC-CRD-01**（P0·正向）岗位卡片字段与空态文案
- 前置：看板存在多条岗位记录，覆盖字段完整、部分缺失、手动录入等场景。
- 步骤：查看岗位看板列表。
- 预期：每张卡片固定展示公司名、岗位名、工作地点、网申截止日期、来源渠道、当前投递状态；公司名 / 岗位名必填不空；工作地点空时展示「地点待定」；截止日期空时展示「未设置」；来源渠道空时展示「手动录入」；当前投递状态空时展示「未投递」。
- 追溯：AC-8、§8.6。

### 3.5 浏览器扩展交互（EXT，AC-3/4/9/10）

**TC-EXT-01**（P0·正向）扩展配置有效 key 后抓取
- 步骤：在 Web UI「设置 → API 密钥」创建 key → 复制到扩展 options 页保存 → 在 BOSS 详情页点击扩展按钮。
- 预期：扩展成功调用 `/jobs/crawl` 并打开预览抽屉。
- 追溯：AC-9、§12.1/12.2。

**TC-EXT-02**（P0·负例）扩展使用无效 / 吊销 key
- 前置：扩展 options 中填入错误 key 或已吊销 key。
- 步骤：点击扩展按钮。
- 预期：后端返回 401；扩展弹窗提示「扩展密钥无效或已吊销，请在扩展设置中更新」；提供打开扩展设置入口。
- 追溯：AC-10、BR-23、§11。

**TC-EXT-03**（P1·异常）本地后端未启动
- 前置：停止本地后端服务。
- 步骤：点击扩展按钮。
- 预期：扩展 catch 网络错误，提示「未检测到 Autohunt 本地服务，请启动应用后重试」；提供手动粘贴入口。
- 追溯：§11、§8 风险 RISK-8。

**TC-EXT-04**（P1·异常）扩展在不支持站点点击抓取
- 步骤：在不在支持清单的页面点击扩展按钮。
- 预期：扩展识别为 unsupported_site，打开 Web UI 手动录入页并预填 URL。
- 追溯：AC-3、FR-30。

### 3.6 安全 / 鉴权 / CORS（SEC，AC-10）

**TC-SEC-01**（P0·负例）`/jobs/crawl` 无有效令牌
- 步骤：分别用无凭证、伪造 key、已吊销 key 调用 `/jobs/crawl`。
- 预期：均返回 401 `UNAUTHORIZED`；响应为统一错误信封；后端不执行解析。
- 追溯：AC-10、BR-23。

**TC-SEC-02**（P0·正向）扩展源 CORS 预检通过
- 步骤：从 `chrome-extension://<extension_id>` 源对 `/jobs/crawl` 发起 OPTIONS 预检。
- 预期：返回 200，`Access-Control-Allow-Origin: *`，`Access-Control-Allow-Headers` 包含 `Authorization`、`Content-Type`、`X-Request-Id`。
- 追溯：§12.2 CORS、技设 §3.3。

**TC-SEC-03**（P1·边界）严格 CORS 模式
- 前置：后端配置 `AUTOHUNT_CORS_ORIGINS=chrome-extension://abc123,moz-extension://def456`。
- 步骤：从允许源与不允许源分别发起 `/jobs/crawl` 预检与实际请求。
- 预期：允许源返回对应 Origin；不允许源无 CORS 头或被浏览器拦截；带有效 Bearer 时安全边界仍成立。
- 追溯：技设 §3.3。

### 3.7 频率限制与 LLM 截断（RAT，AC-11/12）

**TC-RAT-01**（P0·负例）单用户 1 分钟 11 次限流
- 步骤：同一用户（同一 Agent key 或 UI session）在 1 分钟内对 `/jobs/crawl` 发起 11 次独立请求（使用不同 URL / request_id）。
- 预期：第 1~10 次均正常返回 200；第 11 次返回 429 `RATE_LIMITED`，响应含「解析频率过高，请稍后再试」；后续请求在 1 分钟窗口内继续被限流，窗口结束后恢复。
- 追溯：AC-11、BR-31、§12.2。

**TC-RAT-02**（P0·边界）LLM 路径输入 token 超过 8000 截断标记
- 前置：构造公司官网 JD 页面内容，使扩展回传 / 后端拉取的输入 token > 8000。
- 步骤：发起 `source=official` 抓取。
- 预期：后端返回 `ok` 或 `partial`，响应中 `content_truncated=true`；返回的 `fields.description` 为截断后内容；不阻塞解析、不报错。
- 追溯：AC-12、FR-15、BR-30。

### 3.8 回归与边界（REG）

**TC-REG-01**（P1·回归）现有 `/jobs` 端点行为不变
- 步骤：部署后调用现有 `POST /jobs`、`GET /jobs`、`PATCH /jobs/{id}` 各一次。
- 预期：响应形状、状态码、重复提示行为与 PROX-3 接口用例集一致，无回归。
- 追溯：§15 依赖、PROX-3 接口用例。

**TC-REG-02**（P1·边界）source 为 `official` 时扩展可最小化提取
- 步骤：扩展在公司官网页面仅回传 URL、页面 title、少量正文。
- 预期：后端成功接收，走 LLM 路径；扩展端不崩溃。
- 追溯：§8.3 LLM 兜底路径。

## 4. 执行与判门衔接

- 本用例集为 T1 功能用例；T3 执行时（G2.5 部署后）按 `multica-test-automation` 自动化优先：CRW/PRE/DUP/CRD 中涉及 Web UI 可见态的可走 Playwright，扩展交互面可半自动或人工执行，接口断言部分由 API 用例集覆盖。
- 必须与 S1a 技设 §7 验证方式对拍：HTTP 调用成功、Bearer 鉴权、CORS、幂等、失败兜底、不自动保存、Web UI 预览、契约冻结。
- 与 AC 对应关系汇总：AC-1→CRW-01/02 + PRE-02；AC-2→DUP-01；AC-3→CRW-11 + EXT-04；AC-4→CRW-09/10；AC-5→PRE-04；AC-6→PRE-03 + CRW-12；AC-7→CRW-07；AC-8→CRD-01；AC-9→CRW-03/04 + EXT-01；AC-10→SEC-01 + EXT-02；AC-11→RAT-01；AC-12→RAT-02 + CRW-06。
